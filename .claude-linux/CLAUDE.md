# CLAUDE.md

## 基本方針

- シンプルな構成と処理を優先する。
- コメント、コミットメッセージなどには、日本語を使用する。

## 作業の進め方

- 「どこで、誰が実行するか」など手段が曖昧な依頼は、こちらで解釈を確定せず、先に方法を一言で示して確認してから着手する。
- 実行した場所と方法は正確に報告する。実際にやっていないことを「やった」と言わない。

### tmux でコマンドを見せながら実行する

実行の様子を自分で確認できるようにしてほしい旨を伝えられたら、次の手順で実行する。

- このセッションが動いている pane を分割して、別 pane を開く。
  - 分割元は、環境変数 `TMUX_PANE` が指すこのセッションの pane にする。
  - pane を分割すれば別ウィンドウにはならず、ユーザーが別ウィンドウへ移っていても同じウィンドウに開く。
- 開いた pane を宛先に指定して、`send-keys` でコマンドを送って実行する。
- 開いた pane の内容を `capture-pane` で取得して、出力を読み取る。

## コミット

- 変更単位は小さく、こまめにコミットする。
- 変更を反映するたびにコミットしてよい（指示不要）。

## 文章スタイル

### 文章規範スキルの適用

- 日本語でまとまった文章を書くときや推敲するときは、`japanese-tech-writing` スキルを読み込み、その規範に従う。README、設計ドキュメント、PR 説明、報告、記事、解説文を対象とする。
- 作業の主目的が実装や設定変更であっても、その過程でドキュメントを書くなら適用する。依頼が「文章を書いて」の形をしていなくても、対象から外れない。
- 通読させる文章を書くときは、`cognitive-rhythm-writing` も併せて読む。対象は記事、解説文、書籍の章、考察ノートに限る。
- README、手順書、リファレンス、PR 説明に `cognitive-rhythm-writing` を適用しない。読者が目次から必要な箇所へ飛ぶ文書では、未回収の緊張を維持する書き方はかえって読みにくくする。
- コミットメッセージと会話の短い応答は、どちらのスキルも対象としない。

## エージェント活用方針

- 独立タスク（調査、レビュー、テスト等）は複数サブエージェントで並列処理を優先する。
- 文脈窓の節約や待ち時間削減のためのサブエージェント活用も積極的に行う。
